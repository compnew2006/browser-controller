# خطة التحصين الأمني (3 مهام حقيقية + إصلاح ملحق)

بناءً على التحقق من الكود (مش التقرير المضلِّل)، المهام دي كلها موثّقة ومحددة النطاق. كل تغيير ليه blast radius واضح (تم التحقق منه): `ExtensionBridge` مستخدمة بس في `daemon.ts` + `bridge.test.ts`، و`routeCall` ليها caller واحد.

---

## المهمة 1 — نقل الـ token من query string لـ `Sec-WebSocket-Protocol` header (مع backward-compat)

**المشكلة:** الـ token بيتبعت في `?token=` (`bridge.ts:227` server-side، `background.js:129` extension-side). الـ query string بيتسجّل في access logs و history.

**التحدي:** Browser WebSocket API **لا تسمح** بتعديل headers قبل الـ handshake. الطريقة الوحيدة لإرسال token في header هي عبر `Sec-WebSocket-Protocol` subprotocol.

**القرار: Hybrid (آمن ضد breaking):**
- **Server** يقبل token من **مكانين**: subprotocol header (الأولوية) أو `?token=` (legacy fallback). ده بيحمي ضد سيناريو "extension قديمة + daemon جديد" و"العكس".
- **Extension** الجديدة تبعت الـ token في الـ subprotocol **وكمان** في `?token=` (مؤقتًا للـ compat) — نزيله في release جاي.
- **Tests** الجديدة تختبر المسارين (subprotocol + query fallback).

### التغييرات:
1. **`mcp-server/src/bridge.ts`** — في `server.on('upgrade')` (سطر 217-237):
   - استخرج token من `req.headers['sec-websocket-protocol']` (نمط: `bc-auth.<token>`)
   - لو مش موجود، ارجع لـ `url.searchParams.get('token')` (existing behavior)
   - ضيف `handleProtocols` option على `new WebSocketServer({ noServer: true, handleProtocols })` عشان browser يفضل happy (يصدّر `bc-auth` بدون token)
2. **`extension/background.js`** — في `wsUrl()` (سطر 125-130) و`connect()` (سطر 138-150):
   - `new WebSocket(url, ['bc-auth.' + wsToken])` — يبعت الـ token في subprotocol
   - يفضل يبعت `?token=` برضه مؤقتًا للـ compat (لحد release جاي)
3. **`tests/bridge.test.ts`** — زيادة 3 cases: token صحيح في subprotocol / token غلط في subprotocol / token صحيح في query (legacy مايزال شغّال)
4. **Constant-time compare fix (ملحق أثناء العمل):** `bridge.ts:228` بتستخدم `presented !== this.token` (string compare — timing leak). ننقلها لـ constant-time compare زي `daemon.ts:286-298` عشان البوابة الأمنية تكون متناسقة.

## المهمة 2 — Rate limiting per-session (token bucket)

**المشكلة:** مفيش rate limit. Agent في loop يقدر يعمل 1000 click/ثانية ويعمل DoS للـ browser.

**القرار:** Fixed-window token bucket لكل `sessionId` داخل `daemon.ts` في `routeCall` (أول وأوحَد مكان بيمر عليه كل tool call).

### التغييرات:
1. **`mcp-server/src/daemon.ts`**:
   - حقل جديد في `IpcClient`: `rateBudget: number` + `rateWindowStart: number`
   - في `routeCall` أول حاجة: لو الـ window (60s) عدت → reset. لو `rateBudget <= 0` → ارجع error `{ success: false, error: 'Rate limit exceeded (N calls/min). Retry in Xs.' }` بدون ما تنفّذ الـ call (ده كفاية — الـ agent هيقرأ الـ error ويسيبها)
   - Config: `BC_RATE_LIMIT_PER_MIN` (default `120` = 2 calls/sec، سخية بما يكفي لأي agent طبيعي، قاطعة للـ infinite loops)
2. **Test جديد في `tests/daemon.test.ts`**: عميل بيعمل 121 call في دقيقة → آخر call بترفض بـ rate-limit error، أول 120 بتنجح.

## المهمة 3 — `.env.example` + `.gitignore` fix

**المشكلة:** 8 env vars موش موثّقين في ملف، و`.env` مش في `.gitignore` (خطر لو حد حط token حقيقي).

### التغييرات:
1. **`.env.example`** (ملف جديد) — كل الـ 8 env vars الموثّقة من الـ recon، كل واحد بتعليق:
   - `WS_PORT`, `WS_HOST`, `BC_STATE_DIR`, `BC_HEARTBEAT_MS`, `BC_HEARTBEAT_MAX_MISSED`, `BROWSER_CONTROLLER_PROGRESSIVE`, `MCP_AGENT_NAME`, `BROWSER_CONTROLLER_AGENT_NAME`, + الجديد `BC_RATE_LIMIT_PER_MIN`
2. **`.gitignore`** — زيادة `.env` (و`.env.local`) سطر قبل `daemon.log`.
