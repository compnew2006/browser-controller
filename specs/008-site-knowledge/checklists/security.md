# قائمة مراجعة متطلبات الخصوصية والأمان: ملف معرفة الموقع

**الغرض**: تقييم وضوح واكتمال متطلبات حدود البيانات، ومصدر المعرفة، والموافقة، والاستعادة.
**التاريخ**: 2026-11-14
**المواصفة**: [spec.md](../spec.md)

**ملاحظة**: هذه القائمة مراجعة لجودة المتطلبات، وليست اختبارًا للتنفيذ.
**ملكية المراجعة**: يضع المراجع علامة `[x]` فقط بعد الحكم بأن معيار جودة المتطلب مستوفى.
**دلالة العلامة**: `[x]` تعني أن المتطلب واضح وكامل بما يكفي؛ ولا تعني اكتمال التنفيذ.

## Requirement Completeness

- [x] CHK001 هل تحدد المواصفة بوضوح فئات المعلومات المسموحة والممنوعة في الإصدار الأول؟ [Completeness, Spec §FR-007a, §FR-008]
- [x] CHK002 هل تحدد حدود القراءة والكتابة والبحث والتصدير لكل browser profile، بما فيها صلاحية الوكيل المقترن؟ [Completeness, Spec §FR-007b, §FR-007c]
- [x] CHK003 هل تشمل الموافقة العمليات المنفردة والمجموعات والاستيراد، وتحدد المحتوى والنطاق والعملية التي تعتمدها؟ [Completeness, Spec §FR-004, §FR-010, §FR-014, §FR-014a]
- [x] CHK004 هل تحدد حقول المصدر والتواريخ وحالة التحقق، وما يجب عرضه عندما تكون المعلومة مجهولة أو تاريخية؟ [Completeness, Spec §FR-002, §FR-003, §FR-005, §FR-015]
- [x] CHK005 هل توضح المتطلبات أن التصفح أو تلخيص المهمة لا ينشئ معرفة محفوظة تلقائيًا؟ [Completeness, Spec §FR-009, §FR-010]

## Requirement Clarity

- [x] CHK006 هل يُعرَّف «عام عن الموقع» بما يمنع الخلط بينه وبين «متاح للعامة» أو معلومات حساب خاص؟ [Clarity, Spec §FR-007a]
- [x] CHK007 هل توضح المواصفة حدود اكتشاف الأسرار في النص الحر، والمخاطر المتبقية التي يجب أن يقبلها المالك؟ [Clarity, Spec §FR-008, Assumptions]
- [x] CHK008 هل تحدد متطلبات الهوية متى يُرفض الوصول عند جهل هوية الحساب أو تغيّر الموقع أو profile؟ [Clarity, Spec §FR-007, Edge Cases]
- [x] CHK009 هل تحدد المواصفة أن المعاينة يجب أن تعرض كامل المحتوى والنطاق، وما يحدث إذا تعذر عرضهما كاملين؟ [Clarity, Gap, Spec §FR-004, §FR-014]

## Requirement Consistency

- [x] CHK010 هل تتفق القراءة التلقائية للوكيل المقترن مع عزل profiles، وهل يظل مرجع الموقع المرتبط وصفيًا ولا يوسع نطاق القراءة؟ [Consistency, Spec §FR-001, §FR-007b, §FR-007c, §SC-009]
- [x] CHK011 هل تتسق قواعد الموافقة بين الحفظ الجماعي والاستيراد والتعديل والحذف والتصدير؟ [Consistency, Spec §FR-004, §FR-010, §FR-014, §FR-014a]
- [x] CHK012 هل تُستخدم حالات «مخطط» و«منفذ» و«مختبر» و«غير متحقق» باتساق مع المصدر والتاريخ؟ [Consistency, Spec §FR-002, §FR-003, §FR-005, §FR-006]

## Acceptance Criteria Quality

- [x] CHK013 هل يقيس SC-003 رفض العلامات الاصطناعية المعروفة التي يكتشفها الفاحص، مع فصلها عن ضمان كشف كل معلومات الحساب، وهل يقيس SC-003a عزل profiles؟ [Measurability, Spec §FR-007a, §SC-003, §SC-003a]
- [x] CHK014 هل تقيس معايير النجاح أن الأسرار الممنوعة لا تظهر في التخزين أو الردود أو الصادرات أو التشخيص، وأن المقترح المرفوض لا يُحفظ؟ [Measurability, Spec §SC-004]
- [x] CHK015 هل تقيس المعايير أن عناصر الاستيراد أو المجموعة المحفوظة هي العناصر المختارة والمعتمدة فقط؟ [Acceptance Criteria, Spec §SC-005, §SC-008]

## Scenario and Edge Case Coverage

- [x] CHK016 هل تغطي المتطلبات غياب الموافقة، وتغيّر النطاق أثناء انتظارها، والحذف الجزئي، ونتيجة الكتابة غير المؤكدة؟ [Coverage, Spec §FR-004, Edge Cases]
- [x] CHK017 هل تغطي متطلبات الاستيراد المصادر القديمة أو الناقصة والتعارضات والمحتوى غير الموثوق، مع منع اعتباره حالة حية؟ [Coverage, Spec §FR-006, §FR-010, §FR-011, §FR-015]
- [x] CHK018 هل تحدد متطلبات الاستعادة تحذير احتمال عودة بيانات محذوفة، وحق الإلغاء دون تغيير، وحدود النسخ المستعادة خارج النظام؟ [Recovery Flow, Spec §FR-012a, §SC-007, Assumptions]

## Non-Functional Requirements

- [x] CHK019 هل تضع المواصفة حدودًا قابلة للقياس للحجم والعدد وزمن البحث أو تحفظها صراحةً كقرارات تصميم غير ملزمة؟ [Gap, Spec §Success Criteria, Plan §Technical Context]
- [x] CHK020 هل تحدد متطلبات التخزين المحلي والتعطيل والحذف والنسخ القابلة للاستعادة من دون الإيحاء بأن أسماء الملفات أو المراجعة تشفّر البيانات؟ [Security, Spec §FR-012, §FR-013, Plan §Technical Context]

## Dependencies and Assumptions

- [x] CHK021 هل تُعرض افتراضات الثقة في الوكلاء المقترنين ومالك نظام التشغيل وحدود عزل العملاء بوضوح؟ [Assumption, Spec §Assumptions, Research §R2]
- [x] CHK022 هل توضح المتطلبات أن الإرسال لخدمة خارجية للتلخيص لا يحدث إلا باختيار المالك؟ [Dependency, Spec §FR-011]

## Ambiguities and Conflicts

- [x] CHK023 هل تحدد المواصفة الحد الفاصل بين السماح بمعرفة الموقع العامة ورفض المعلومة التي قد تعرّف شخصًا؟ [Ambiguity, Spec §FR-007a, §FR-008]
- [x] CHK024 هل تحسم المتطلبات ما الذي يُعرض للمراجع عند كبر المحتوى أو نقص الدليل بدل الاعتماد على ملخص قد لا يمثل ما وافق عليه؟ [Ambiguity, Gap, Spec §FR-004, §FR-010]

## Notes

- النطاق: مراجعة أمن البيانات، وعزل الوصول، ومصدر المعرفة، وموافقة المالك.
- العمق: قياسي؛ الجمهور: مراجع المواصفة قبل التخطيط أو التسليم.
- تبقى قائمة `requirements.md` العامة دون تعديل.
- مراجعة المتطلبات: CHK001–008 مغطاة في FR-002–003 وFR-007–010 وافتراضات الثقة؛ قبول خطر النص الحر موثق في الخطة ولا يعني ضمان الكشف. CHK009 وCHK024: أضيف إلى FR-004 اشتراط العرض الكامل والرفض عند تعذره وبيان الدليل الناقص.
- CHK010–012: راجع FR-001–007c وFR-014a، وعقد النطاق والاعتماد؛ مرجع الموقع وصفي، والمجموعة مرتبطة بالمحتوى والنطاق، وحالات التنفيذ والدليل منفصلة. CHK013–015: راجع SC-003–005 وSC-008؛ وُضّح SC-004 ليقيس العلامات المكتشفة دون ادعاء كشف شامل.
- CHK016–018: راجع الحالات الطرفية وFR-012a وSC-007 وعقد الحذف والاستعادة؛ فشل الحذف الجزئي والنتيجة المجهولة والاستعادة الخارجية لا تُعرض كعمليات ذرية مضمونة. CHK019–020: حدود الموارد والأداء مقترحة صراحةً في الخطة، والتخزين غير مشفر وفق سياقها التقني.
- CHK021–023: راجع الافتراضات وFR-007a وFR-008 وFR-011 وقسم الثقة في العقد: عميل مقترن موثوق وحدود اكتشاف الهوية والنص الحر، وعدم إرسال المحتوى خارجيًا دون اختيار المالك، والتمييز بين الأدوار العامة وبيانات الأشخاص والحسابات.
- الأحكام تخص وضوح المتطلبات والتصميم فقط؛ لا تثبت التنفيذ أو أهلية عميل الموافقة. ما زال اختبار P0 الفعلي ورفض الكتابة افتراضيًا مطلوبين قبل الاستخدام الحقيقي.
