# عقد معرفة الموقع المقترح

هذه عقود تخطيطية غير منفذة. تنطبق قرارات [spec.md](../spec.md) وحدود [data-model.md](../data-model.md). الأسماء النهائية تُضاف للـ registry الوحيد وتُمرر عبر wire مع اختبارات drift، ولا تُنشأ aliases أو جداول timeout موازية.

## نطاق الثقة العام

- يُختار browser profile بالطريقة الحالية للجلسة. تكون أدوات الوكيل tab-scoped وتستخرج origin/profile/connection/session من تبويب متاح وسياق extension، وليس من مدخل الوكيل. تُرفض الطلبات ذات مفاتيح غير معروفة بما فيها `browserId`, `origin`, `ownerConfirmed`, `digest` المستخدم للمصادقة، أو محتوى يتجاوز الحدود. لا يستطيع سياق مرتبط بملف تغيير scope إلى ملف آخر عبر معاملات الأداة؛ استخدام ملف آخر يتطلب سياقًا مستقلًا ومصرحًا به له.
- `default` أو هوية مكررة، سياق غير ثابت أو غير top-level أو incognito، vault محمي/مجهول، تغيّر origin أو اتصال أو profile، أو policy معطلة/مستبعدة → رفض مغلق دون قراءة/كتابة المعرفة. يجب إثبات الربط عند كل طلب وعند commit.
- كل وكيل مقترن مسموح له باستخدام profile يقرأ معرفته العامة تلقائيًا. عميل موثوق يستطيع اختيار profile متصل؛ العزل هنا يمنع الخلط بين مخازن profiles، وليس حاجزًا أمنيًا أمام حامل IPC token أو مستخدم محلي عدائي. لا تستورد البيانات الخاصة بحسابات الموقع في P1.
- الميزة opt-in مستقلة؛ عند تعطيل أو استبعاد الذاكرة الحالية يُرفض استخدام المعرفة الجديدة كذلك، ولا يُغيَّر السلوك الحالي. يلزم تعريف عملية سياسة الميزة وموافقة المالك عليها قبل أي تشغيل.
- تتضمن سياسة 008 عمليات owner-approved للتمكين والتعطيل والاستبعاد والإدراج؛ التعطيل والاستبعاد يبطلان المسودات قبل السماح بعمليات لاحقة. تظل السياسة الحالية مرجعًا إضافيًا، ولا تكفي سياسة 008 لإلغاء استبعاد قائم.
- واجهة المالك المقترحة هي `scripts/memory.mjs` بأوامر `knowledge policy enable|disable|exclude|include`، ضمن سياق profile يختاره المالك محليًا وorigin عند الاستبعاد/الإدراج. تعرض العملية والنطاق والسياسة الحالية والنتيجة المتوقعة في جلسة تفاعلية محلية، وتطلب تأكيدًا صريحًا لكل تغيير؛ ترفض الوضع غير التفاعلي والرفض وانقطاع الجلسة، ولا تقبل تأكيدًا من معاملات الوكيل. تحدد مهمة التنفيذ أسماء الخيارات بعد فحص CLI القائم وتختبرها من الطرف إلى daemon. هذه الواجهة ليست ACL ضد مستخدم محلي أو حامل token خبيث.
- يجب أن يشمل حذف الموقع أو `delete --all` القائم المعرفة الجديدة أيضًا، حتى لا يبقى محتوى يتوقع المالك حذفه. يُحجز منع القراءة والكتابة ويُبطل العمل المعلق قبل الحذف عبر المخازن؛ إن فشل حذف أي مخزن تُبلغ العملية بفشل جزئي صريح وتبقى البيانات المحجوبة غير قابلة للقراءة حتى استكمال التنظيف. يُحفظ سجل تقدم محدود بلا محتوى في حالة آمنة قابلة للاستكمال بعد restart. لا يُدّعى أن الحذف بين ملفات متعددة transaction ذري، ولا يغيّر هذا عقود 003/004 من حيث النجاح أو الصلاحيات دون اختبارات ومراجعة توافق.
- قبل أي حذف فعلي، يجب تثبيت سجل الحجب بلا محتوى على وسيط دائم وإعادة تحميله قبل إتاحة قراءات المخازن المعنية بعد restart؛ فشل إنشاء السجل أو إثبات دوامه يوقف العملية قبل المساس بالمخازن. لا يُرفع الحجب إلا بعد إثبات اكتمال التنظيف وتثبيت حالته؛ عند تعذر ذلك يُرفض الوصول ويُطلب الاستكمال. يُبلّغ الفشل الجزئي دون الادعاء بأن البيانات المتغيرة قد استُعيدت.

## `browser_site_knowledge` — قراءة فقط

مقترح الإدخال: `{ tabId: integer, action: "read" | "search", category?: enum, query?: string, cursor?: string }`. الحدود: query حتى 160 حرفًا، الصفحة حتى 20 عنصرًا و8 KiB، مع cursor opaque مربوط بالنطاق والفلتر وإصدار السجل؛ cursor خاطئ أو قديم يرفض أو يطلب إعادة البحث. لا يسمح batch/tabs بصياغة لتجاوز نطاق الجلسة.

كل نتيجة تتضمن `id`, category, subject, body, source/attestation, observedAt, lastVerifiedAt, status, execution/testOutcome عند انطباقها، و`relatedIds` داخل الملف الحالي. وقد تتضمن قراءة ملف الموقع `relatedSites` كمرجع origin وعلاقة ومصدر فقط. تُوسم صراحةً بأنها بيانات غير موثوقة. تُعرض الادعاءات المتعارضة كما هي وبمصادرها؛ لا يُنفّذ محتواها. لا يكشف الرد معلومات profile آخر أو عناصر خاصة بحساب، ولا يتبع مرجعًا إلى origin آخر. لا توجد موافقة قراءة إضافية بعد تحقق النطاق.

## `browser_site_knowledge_manage` — معاينة ثم اعتماد

العمليات المقترحة `prepare_add`, `prepare_edit`, `prepare_delete`, `prepare_export`, `prepare_restore`, ثم `confirm` أو `cancel`. الإدخال العام يتضمن `tabId`, operation، العناصر المختارة المحدودة، ومعرّف عنصر و`expectedRevision` للتعديل/الحذف؛ لا يتضمن profile أو origin أو approval proof من الوكيل. `prepare_restore` في P2 ويأخذ artifact محليًا اختاره المالك عبر واجهة مالك محددة في التنفيذ لا مسارًا اعتباطيًا قابلًا لقراءة أسرار الجهاز. الاستيراد إلى draft متأخر إلى P4؛ لا fetch للشبكة.

1. Validate: حقول وأنواع وقيم محدودة، رفض حقول مجهولة وأسرار/حسابات خاصة مكتشفة، وربط scope؛ لا echo للمحتوى المرفوض.
2. Prepare للعمليات العادية: إنشاء draft مؤقت 5 دقائق بأقصى 8 عناصر و4 KiB للمعاينة الكاملة، مع revision وgeneration. الاستعادة تستخدم `RestoreDraft` بحدودها المستقلة أدناه. نتيجة التحضير تتضمن معرفًا opaque، ونطاقًا آمنًا ومعاينة المحتوى التي ستُعرض للمالك؛ هذا محتوى غير موثوق، ولا يُكتب للقرص.
3. Confirm: الخادم يعرض للمالك **كل** العناصر المختارة، مصادرها، نوع العملية، الموقع واسم profile والتحذيرات؛ موافقة واحدة تخص هذه المجموعة فقط. selection يحدث قبل confirm، وتعديله ينشئ draft جديدًا. صياغة الرسالة تزيل محارف التحكم المضللة ولا تغير المحتوى الموافق عليه بصمت. الرفض، الغياب، عدم دعم elicitation، انتهاء المهلة، عدم القدرة على إظهار كل المحتوى أو إعادة إرسال التأكيد → لا كتابة.
4. Commit: داخل serial section يُعاد اشتقاق ومقارنة session/connection/profile/origin والسياسة وrevision/generation وبصمة canonical للمجموعة. الانقطاع أو تبدل الصفحة أو سياسة الحذف أو المحتوى أو النسخة → `SCOPE_CHANGED` أو `STALE_REVISION`؛ لا تُستهلك موافقة في نطاق آخر. الدفعة الذرية تقتصر على ملف واحد، ولا نجاح جزئي.
5. Response: `success` ومعرّفات وتعديل revision بعد commit المؤكد فقط؛ لو أُنجز rename مع فشل إثبات الدوام فـ `OUTCOME_UNKNOWN` مع إرشاد فحص السجل، لا retry تلقائي. لا نصوص حساسة في الأخطاء أو السجلات. تتوافق رموز الأخطاء النهائية مع سجل `ERROR_CODES` بالمشروع بدل اختراع alias موازٍ.

هذه العملية واجهة للعميل الموثوق والمستخدم؛ سجل digest وflags لا يحمي من حامل token يستطيع تجاوز واجهة MCP، وهو خارج ضمان الأمان الحالي. P0 يثبت أن واجهة العميل تعرض المعاينة كاملة فعلًا، وإلا لا تتاح الكتابة إلى أن يتوفر مسار مراجعة مالك مناسب.

## الاستعادة والتصدير

Export لملف `(profile, origin)` محدد فقط مع حدود حجم وقراءة كاملة وflush مثبت؛ لا يحتوي drafts أو بيانات محظورة. الاستعادة المدارة في P2: فحص نسخة اصطناعية/محددة، schema/version وحجم ونطاق، ثم معاينة كاملة وتأثير الاستبدال وتحذير من احتمال رجوع المحذوف، تليها موافقة صريحة مرتبطة بالـ digest والنطاق/revision. المعاينة متعددة الصفحات يجب أن تُراجع بالكامل وتُربط بإقرار واحد؛ إن لم تستطع الواجهة إظهارها كاملة ترفض العملية. كل تأكيد يخص موقع/profile واحدًا فقط. رفض/تعطل قبل commit لا يغير الملف؛ لا تضمن الأداة شيئًا عن استعادة خارجية.

تستخدم الاستعادة `RestoreDraft` المنفصل وحدوده وتسلسل مراجعة الصفحات في نموذج البيانات؛ لا يطبق عليها حد 8 عناصر الخاص بالدفعات. لا يُقبل إقرار الصفحات أو الموافقة إلا من واجهة مالك اجتازت اختبار العرض الفعلي في P0، مع إعادة التحقق من digest وrevision والنطاق عند commit. إقرار الصفحة إجراء للمراجعة لا برهان تقني على انتباه الإنسان أو قراءة النص.

## مصادر أدلة ملخص المهمة

لا يُعد نص يقدمه الوكيل دليلًا مستقلًا على تنفيذ أو اختبار. يقبل الملخص أحداثًا اصطناعية للاختبار، وأحداثًا فعلية فقط من مسار جلسة موثوق ومحدد يستطيع ربط العملية ونتيجتها ووقتها بنطاق المهمة دون نسخ محتوى حساس. لا يُفترض وجود هذا المسار: على P3 فحص المتاح وإثباته؛ إذا تعذر ذلك تُعرض التفاصيل كـ `declared` و`unverified`، ولا تُسند حالة اختبار مثبتة أو تنفيذ مثبت. موافقة المالك على الحفظ لا تحول الادعاء إلى دليل مستقل.

## الفحوص الإلزامية

- profiles A/B لنفس origin، تبديل الجلسة، default/duplicate identity، انقطاع/إعادة اتصال وتغير tab/origin؛ لا محتوى scope آخر في read/search/export/errors.
- جلسة مصرح بها ومرتبطة بـ A تقرأ A دون elicitation إضافي للقراءة، وترفض تغيير scope إلى B من مدخل الوكيل؛ جلسة مستقلة ومصرح بها لـ B تقرأ B فقط. مرجع related-site في A لا يبدأ قراءة أو بحثًا أو تصديرًا لـ B ولا يورّث صلاحية أو بيئة.
- تأكيد عنصر أو مجموعة، رفض وعدم إجابة وعميل بلا elicitation، محتوى مبتور، تبديل selection/source/revision/profile، replay/expiry، abort وسباق delete/disable؛ لا partial commit.
- علامات أسرار وبيانات شخصية اصطناعية في كل واجهة ومصادر وروابط وdiagnostics وbackup؛ تقييم حالات عدم اكتشاف متوقعة دون وعد بكشف كامل.
- ادعاءات متعارضة وتواريخ مفقودة، provenance غير مثبت، سجل قديم، limits/pagination/cursor، UTF-8 وعربي ومحارف تحكم.
- فشل temp write وrename وfsync، restart، استعادة نسخة قبل الحذف، artifact تالف/مستقبلي، downgrade، وتوافق ملفات 003/004. اختبار النتائج المجهولة وعدم تكرار side effects.
- الحذف الحالي لموقع أو كل المواقع مع فشل أحد المخازن وrestart: لا نجاح كاذب، لا ظهور للمعرفة المحجوبة، واستكمال التنظيف دون إحياء مسودات قديمة.
