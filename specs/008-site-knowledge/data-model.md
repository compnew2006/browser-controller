# نموذج بيانات معرفة الموقع

هذه أنواع وتصميمات مقترحة لا تعكس بيانات حالية. النطاق والتفويض والحدود في [contracts/site-knowledge.md](contracts/site-knowledge.md) و[plan.md](plan.md).

## Scope وKnowledgeFile

- **Scope**: `browserId` غير افتراضي، canonical HTTP(S) `origin`، وهوية connection وsession الفعلية. للأدوات العامة تُشتق القيم من اتصال extension وسياق tab، ولا تُقبل هوية profile يزوّدها الوكيل. لا هوية حساب في P1؛ البيانات الخاصة بحساب مرفوضة.
- **KnowledgeFile**: `schemaVersion: 1`، `browserId`، `origin`، `revision` عدد صحيح متزايد، `updatedAt` UTC، و`entries` و`relatedSites` محدودتان. يخزن مستقلاً عن `memory/sites` و`memory/maps` في مسار مشتق باستخدام hash للـ profile وorigin. `browserId` وorigin الموجودان داخل الملف يُقارنان بالنطاق المشتق؛ الاسم المجزأ ليس ACL أو تشفيرًا.
- ملف واحد بحد 128 KiB و100 عنصر؛ 500 ملف للـ profile و32 MiB إجمالي. عند بلوغ الحد ترفض الكتابة دون حذف قديم تلقائيًا. الحدود أولية لمراجعة المالك ويمكن تعديلها في الخطة قبل التنفيذ، لا عبر جداول منفصلة عن validators.
- النسخة غير المدعومة أو الملف غير الصالح لا يُستبدل ولا يُحذف تلقائيًا؛ تظهر حالة محددة دون بيانات حساسة. التحول بين إصدارات 008 يتطلب migration منفصلًا بموافقة، وليس أثناء القراءة.

## RelatedSite

- `relatedSites` قائمة بحد أقصى 20 مرجعًا وصفيًا محفوظة داخل ملف الموقع المصدر. يتضمن كل مرجع `origin` canonical مختلفًا عن origin الملف، وعلاقة من `same_product | staging_for | production_for | other`، ومصدرًا و`attestation` وفق حقول `KnowledgeEntry.source`، و`observedAt` كـ UTC أو null. تُرفض origins غير الصالحة أو المكررة داخل الملف.
- تُراجع تغييرات القائمة مع محتوى ملف الموقع المصدر وتدخل في بصمة الموافقة ونسخته. العلاقة ادعاء منسوب لمصدر وليست دليلًا على البيئة أو التفويض، ولا تُستنتج من اسم المضيف.
- عند قراءة ملف المصدر، يُعاد مرجع العلاقة فقط. لا يُفتح origin الهدف ولا تُقرأ أو تُبحث أو تُصدّر بياناته، ولا تنتقل العلاقة أو صلاحيات القراءة عبر سلسلة علاقات. لقراءة الهدف يجب اشتقاق scope مستقل من سياق مصرح به لذلك الـ origin والـ profile.

## KnowledgeEntry

- `id`: معرّف عشوائي ثابت يُنشئه daemon؛ لا يحمل اسم المستخدم أو محتوى.
- `category`: `site`, `role`, `function`, `problem`, `change`, `test`؛ أسماء أدوار عامة فقط، دون account IDs أو أسماء أشخاص.
- `subject`: موضوع قصير قابل للبحث؛ النص والقيم مصنّفان غير موثوقين. `body` نص مختصر قابل للمراجعة، وحد العنصر الإجمالي 2 KiB UTF-8. تُرفض الحقول غير المعروفة، محارف التحكم المضللة، URLs ذات userinfo أو query/fragment، والأسرار والمعلومات الحساسة المكتشفة. الحفاظ على العربية يتطلب تطبيع Unicode متسقًا دون إزالة النص المشروع.
- `source`: نوع `owner_statement`, `direct_observation`, `historical_record`, `task_summary`، ومرجع اختياري آمن، مع تمييز `attestation: corroborated | declared`. مصدر وكيل لا يثبت نفسه؛ إذا لم يوجد دليل جلسة يمكن ربطه بالنتيجة يبقى declared/unverified. لا يُفتح المرجع تلقائيًا.
- `observedAt` و`lastVerifiedAt`: UTC أو null عندما لا يُعرف؛ `createdAt` و`updatedAt` UTC يسجلهما النظام. لا يُفترض أن وقت الإدخال وقت الملاحظة.
- `status`: `unverified`, `verified_at_time`, `historical`, `needs_recheck`؛ نجاح الاختبار يتطلب دليلًا ووقت تحقق. `execution`: `planned`, `performed`, `unknown`, `not_applicable`؛ `testOutcome`: `not_run`, `passed`, `failed`, `unknown`, `not_applicable`.
- `relatedIds`: روابط داخل نفس scope لمعلومة مشكلة/تغيير/اختبار أو ادعاءات متعارضة؛ لا تستخدم لتمثيل موقع آخر. تُستخدم `relatedSites` للعلاقة بين origins كما سبق، دون جلب بيانات أي موقع آخر. العلاقات لا تستبدل أي ادعاء تلقائيًا.

التحقق من detector best-effort لا يضمن خلو أي نص حر من الأسرار؛ تُرفض علامات الاختبار المعروفة وتلزم مراجعة المالك ولا يُزعم ضمان يتجاوزها. لا تحفظ المدخلات الحساسة المكتشفة حتى في رسائل الرفض.

## Draft وApprovalBinding

`Draft` كائن في ذاكرة daemon فقط وله id عشوائي و`createdAt`, `expiresAt` (5 دقائق بحد أقصى مع ساعة monotonic لمنع إطالة المهلة عند تغيير ساعة النظام)، عملية، اختيار مرتب، نطاق مشتق، revision متوقع وجيل policy/delete، وpayload canonical بعد التحقق. يحوي عناصر محددة لموقع/profile واحد فقط؛ لا يكتب إلى logs أو disk أو مقترحات دائمة. حد الدفعة 8 عناصر و4 KiB في المعاينة الكاملة، وحد المسودات المعلقة 128 لكل عملية daemon؛ يُرفض ما لا يمكن عرضه كاملًا في واجهة التأكيد.

`ApprovalBinding` يتضمن digest للـ canonical payload، والعملية، session وconnection وprofile وorigin، revision وجيل السياسة/الحذف ووقت الانتهاء. البصمة تمنع اختلاف المحتوى ضمن السياق الموثوق ولا تثبت تفويضًا أمام عميل مقترن خبيث. تُستهلك الموافقة مرة واحدة، وتُمحى عند انتهاء أو إلغاء أو انقطاع أو حذف أو تغيّر النطاق أو restart. لا يستقبل عقد MCP حقول تأكيد من الوكيل؛ لا يعتمد daemon على boolean قابل للتزوير كحد أمان ضد حامل token موثوق.

## Lifecycle والتزامن

`proposed → validated → previewed → approved → committed`؛ والإلغاء أو الرفض أو انتهاء الصلاحية أو تغيّر scope/revision/policy ينتقل إلى `discarded` دون كتابة. تغيير الاختيار أو النص أو المصدر أو العملية بعد المعاينة يتطلب draft جديدًا. تحديث معلومات متعارضة لا يزيل الأخرى؛ تعديل سجل يحتاج revision متوقعًا، وحذف سجل يمحوه بعد موافقة مستقلة ويبطل المقترحات التي تعيد إنشاءه.

تُسلسَل تغييرات نفس الملف بواسطة كاتب daemon واحد وتُعاد جميع فحوص النطاق والموافقة والنسخة تحت التسلسل قبل atomic replace. الدفعة صالحة بالكامل أو لا يُكتب منها شيء. ذاكرة idempotency محدودة الوقت والحجم تربط request ID بالبصمة والنطاق والنتيجة؛ لا تَعِد exactly-once عبر restart. إن حدث rename ولم يتأكد fsync فالنتيجة `OUTCOME_UNKNOWN`؛ لا يُعاد الإرسال تلقائيًا، ويُفحص revision/محتوى السجل أولًا.

## Restore وExport

Export مُرقّم الصفحات أو artifact محدود لنطاق واحد، دون معرفة profile آخر، ويُستبعد منه draft وcredentials. استعادة مدارة تُحلل نسخة واحدة ضمن حدود الحجم والإصدار والنطاق، ثم تعرض كل التغييرات والتحذير من إعادة معلومات محذوفة، ويدعم عقد المراجعة عرضًا كاملًا متعدد الصفحات مع ربط digest واحد. إن لم تستطع واجهة المالك إثبات إظهار المعاينة الكاملة يُرفض الاستيراد/الاستعادة ولا تُستخدم معاينة مبتورة. موافقة المالك قبل atomic replace ضرورية؛ لا يزعم النظام منع استعادة مباشرة خارج أدواته أو معرفة كل المحذوفات من نسخة قديمة.

`RestoreDraft` مستقل عن حد الدفعة العادية (8 عناصر و4 KiB): يحتفظ في ذاكرة daemon فقط بملف واحد صالح حتى 128 KiB و100 عنصر، ونطاقه وrevision وgeneration وdigest والمراجعة المرتبة للصفحات. يُعرض كل نص وتأثير الاستبدال والتحذير بصفحات لا يتجاوز محتواها 4 KiB، مع أرقام وترتيب واضحين وإقرار محلي بكل صفحة قبل التأكيد النهائي. الحد الأقصى للمراجعة 30 دقيقة، وعند انتهائها أو الانقطاع أو restart أو تغير أي محتوى أو نطاق أو revision تُلغى ويبدأ استعراض جديد. لا يكفي عداد صفحات لإثبات أن واجهة العميل عرضتها كاملة؛ لا يُسمح بالاستعادة إلا عبر واجهة أثبتتها بوابة P0 للعرض والتفاعل. تُربط الموافقة الواحدة ببصمة الملف والنطاق والعملية وترتيب الصفحات وتُستهلك مرة واحدة.
