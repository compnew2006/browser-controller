# دليل التحقق المخطط: معرفة الموقع

الميزة غير منفذة. هذا الدليل يحدد ما يجب تشغيله **بعد التنفيذ**؛ أسماء أدوات 008 وملفات اختباراتها أدناه مقترحة، وليست أوامر ثبت نجاحها الآن. لا تستخدم بيانات حقيقية أو profile المستخدم أو credentials فعلية.

## التجهيز

1. استخدم checkout/نسخة عمل معزولة، Node بإصدار مدعوم، وdependencies مطابقة للـ lockfile. `npm ci` ينشئ `node_modules`؛ شغّله داخل النسخة المعزولة فقط إذا لزم.
2. وجّه daemon تحت الاختبار إلى state directory مؤقت فارغ وبصلاحيات المالك، واستخدم ports عشوائية وامتدادًا وموقعًا اصطناعيين؛ لا تبدأ أو توقف daemon المستخدم. راجع `tests/helpers/memory-fixtures.ts` و`scripts/smoke-vault-isolated.mjs` قبل التشغيل.
3. بعد تطبيق التغييرات، افحص scripts قبل تشغيلها ثم نفذ داخل النسخة المعزولة:

```sh
npm run build
npm test -- tests/site-knowledge*.test.ts
npm run lint
npm run typecheck
npm run arch:check
npm run test:coverage
npm run security:audit
npm run context:lint
npm run context:measure
```

أسماء اختبار `site-knowledge*.test.ts` توضع أثناء التنفيذ وتُستبدل بالأسماء الفعلية قبل اعتماد هذا الدليل؛ إن لم توجد فلا يُسجل الأمر كاختبار ناجح. `build` ينظف `dist` ويولد ملفات، لذلك لا يُستخدم فوق مخرجات المستخدم دون مراجعة. اختبر Node minimum/latest كما ينص CI وعلى Windows عند توفر بيئة آمنة؛ سجّل ما لم يُشغَّل.

## السيناريوهات والنتائج المتوقعة

**بوابة P0 قبل الاستخدام الحقيقي:** اختبر عميل المالك الفعلي ببيانات اصطناعية فقط، وسجّل إصداره ونتيجة عرض نص طويل ونطاق وتحذيرات وصفحات متعددة وحالات الاقتطاع والانقطاع. إثبات عرض الواجهة لا يثبت انتباه الإنسان. يجوز تطوير الميزة واختبارها في بيئة معزولة قبل اجتياز البوابة، لكن لا تُفعّل الكتابة على بيانات فعلية ولا تُسلّم للاستخدام حتى تتوفر واجهة مؤهلة ويقبل المالك صراحةً الخطر المتبقي للتعامل مع النص الحر. الموافقة على مراجعة وثائق التصميم ليست قبولًا تشغيليًا لهذا الخطر.

**أداة اختبار العرض المعزولة:** `specs/008-site-knowledge/p0-elicitation-probe.mjs` خادم MCP تجريبي مستقل، لا يتصل بـ Browser Controller أو Chrome أو مخازن المستخدم ولا يحفظ بيانات. لتوصيله مؤقتًا بعميل Codex CLI جديد من جذر المستودع، دون تغيير إعدادات MCP الدائمة:

لاختبار البروتوكول آليًا قبل فحص الواجهة، شغّل `node --test specs/008-site-knowledge/p0-elicitation-probe.test.mjs`. هذا الاختبار يستخدم عميلًا اصطناعيًا ولا يثبت العرض البصري.

```sh
codex -c 'mcp_servers.site_knowledge_p0.command="node"' \
  -c "mcp_servers.site_knowledge_p0.args=['$PWD/specs/008-site-knowledge/p0-elicitation-probe.mjs']"
```

داخل الجلسة الجديدة اطلب استدعاء `site_knowledge_preview_probe`. على المراجع التأكد بصريًا من الموقع والتحذير وبداية ونهاية كل صفحة (`END-PAGE-1`, `END-PAGE-2`, `END-PAGE-3`) وإمكانية الوصول لكل النص عند التمرير قبل الرد. كرر مع الرفض أو إغلاق الواجهة؛ يجب توقف الاختبار دون أي عملية. دوّن نسخة العميل وطريقة عرضه والنتائج؛ لا يُعتبر تأكيد العميل وحده أو نجاح اتصال MCP إثباتًا للعرض. اختبار CLI يؤهل تلك الواجهة والإصدار المختبرين فقط، ولا يثبت سلوك Codex Desktop أو أي عميل آخر. لا تدّعِ نجاح T006 دون استكمال حالات الاقتطاع والتغيّر والانقطاع المحددة في المهمة.

1. **التمكين والنطاق**: قبل تمكين معرفة الموقع، قراءة/كتابة ترفضان دون تسجيل محتوى؛ استخدم واجهة السياسة التفاعلية المقترحة في `scripts/memory.mjs` بموافقة مالك اصطناعي، واختبر enable/disable/exclude/include والانقطاع والوضع غير التفاعلي. اربط profile A وB بنفس origin؛ جلسة A المصرح بها تقرأ A دون elicitation أو طلب موافقة قراءة، ومحاولة تغيير scope إلى B بمعرّف يقدمه الوكيل تُرفض. اختبر أن B لا يعرض معرفة A في read/search/export؛ جلسة مستقلة ومصرح بها لـ B تقرأ B فقط. لا يثبت ذلك حماية ضد حامل IPC token الخبيث.
2. **المعاينة والموافقة**: اقترح دفعة من ثلاثة عناصر عامة، اختر عنصرين واستعرض النص والمصدر والنطاق كاملًا ثم وافق؛ يظهر العنصران فقط. اختبر الرفض، عدم وجود elicitation، timeout، انتهاء draft، replay، عميل يخفي أجزاء المعاينة، وتغيير نص أو اختيار بعد الموافقة؛ لا كتابة لأي منها. اختبر write في session read-only وtab غير مملوك: يجب الرفض.
3. **تغير النطاق والسباق**: بينما الموافقة معلقة بدّل origin أو profile أو connection، أو احذف/عطّل/استبعد الموقع، أو غيّر revision من طلب آخر؛ لا يُكتب draft القديم. اختبر duplicate profile و`default` وincognito وvault protected/unknown وtab غير مستقر.
4. **الخصوصية**: أدخل علامات اصطناعية معروفة ومحددة مسبقًا تمثل كلمة مرور، token، cookie، مفتاح API، بيانات دفع، معرّف حساب، وURL يحمل query/credentials؛ إذا اكتشفها الفاحص تُرفض ولا تصل إلى السجل أو الرد أو stderr أو export أو artifacts، مع اختبار نص عربي ومحارف تحكم. راجع حالات detector الفائتة عمدًا؛ لا تتوقع كشف معرّف حساب مجهول ولا تثبت النتائج كشف كل الأسرار في نص حر.
5. **الدليل والتعارض**: اعتمد معلومتين متضادتين بتواريخ ومصادر مختلفة، وإصلاحًا مخططًا وآخر منفذًا واختبارًا فاشلًا؛ البحث يعيد المصدر والحالة والتاريخ، ولا يسمي المخطط ناجحًا أو القديم حالة حالية. شهادة الوكيل بدون دليل موثوق تظهر `declared`/غير متحققة.
6. **الاستعادة**: صدّر بيانات اصطناعية لـ A، احذف عنصرًا، ثم عاين استعادة النسخة القديمة. يظهر تحذير رجوع المحذوف وكل التأثير؛ الرفض/إغلاق أو عدم ظهور المعاينة كاملة يترك المخزن كما هو. عند الموافقة الصريحة تُستعاد مجموعة النطاق المعروض فقط. اختبر نسخة تالفة أو مستقبلية أو أكبر من الحد؛ النسخ الخارجية خارج سيطرة هذا الاختبار.
7. **فشل الكتابة والرجوع**: احقن فشلًا قبل rename وبعده وعند fsync، واختبر `OUTCOME_UNKNOWN` من غير retry آلي. بعد تشغيل fixture قديم وحديث، تحقق byte-for-byte أن ملفات 003/004 لم تُعد كتابتها، وأن إصدارًا قديمًا يعمل بعد تعطيل 008، وأن مخزن 008 لم يُحذف تلقائيًا.
8. **الملخص والاستيراد لاحقًا**: في P3، اقترح ملخصًا بدون حفظ واختبر التمييز بين المنفذ والمخطط. في P4، استخدم ملفًا اصطناعيًا محليًا مخصصًا للمالك مع بيانات محظورة؛ لا كتابة قبل اختيار وموافقة معاينة كاملة، ولا يُرسل المحتوى لخدمة خارجية.
9. **علاقة موقع بموقع**: اعتمد مرجعًا اصطناعيًا من A إلى B في ملف A؛ يجب أن تعرض قراءة A المرجع والمصدر فقط دون استدعاء أو جلب أو تصدير بيانات B. لا تنتقل العلاقة أو صلاحية الوصول، وتقرأ جلسة مستقلة ومصرح بها لـ B ملف B من سياق B فقط.

## سجل النتائج

لكل تشغيل دوّن commit وحالة working tree، النظام وNode، نوع المتصفح/profile المعزول، الأوامر وexit codes، أسماء الفحوص الناجحة والفاشلة، حدود التغطية، وأي تحذير موافقة أو استعادة غير قابل للتنفيذ. لا تُدرج محتوى السجلات الاصطناعية المصممة كأسرار أو أي بيانات مستخدم فعلية. اختبارات الصيغ لا تثبت أمنًا شاملًا أو عزل عملاء محليين عدائيين.

**تشغيل جزئي 2026-11-14:** macOS وNode `22.23.1`، على نسخة ملفات مؤقتة معزولة من working tree المعدّل، دون daemon المستخدم أو profile حقيقي. نجح `npm run build` و`npm run lint` و`npm run typecheck` و`npm run arch:check`؛ ونجحت اختبارات `tests/site-knowledge*.test.ts` (16 ملفًا و186 اختبارًا). نجح `npm run test:coverage` بعد تضمين ملفَي CI وقواعد المشروع المتتبعين في النسخة المعزولة: 197 ملف اختبار و2964 اختبارًا. فشل التشغيل الأول بأربعة أخطاء ملفات غير موجودة لأن النسخة الأولى استبعدت هذين الملفين؛ لم تُغيّر الاختبارات لتجاوزها. تغطي النتائج الكود الحالي فقط ولا تثبت اكتمال الميزة أو نجاح P0. لم تُشغّل هنا اختبارات واجهة مالك فعلية أو audit يتصل بخدمة خارجية.

نجح أيضًا اختبار بروتوكول probe الاصطناعي بست حالات، ونجح `npm run context:lint` و`npm run context:measure` للـ checkout الفعلي. اختبار البروتوكول لا يثبت عرض المعاينة في واجهة مالك فعلية.

بعد اختبار التغطية، نجح تشغيل `tests/daemon-wire-tools.test.ts` و`tests/site-knowledge-approval.test.ts` (11 اختبارًا) متضمنًا رفض اسم أداة الكتابة عبر IPC مصادق عليه وMCP وbatch في الحالة الحالية؛ لا يغطي ذلك CLI أو تكامل كتابة مستقبليًا.

بعد تعديل التحقق قبل المعاينة، أُعيد build و`npm run test:coverage` في النسخة نفسها ونجح 2966 اختبارًا في 197 ملفًا؛ ونجحت اختبارات الميزة وIPC المستهدفة (193 اختبارًا) وlint وtypecheck وarch:check. ظهرت في checkout الفعلي أثناء العمل تعديلات مستقلة على `package.json` و`package-lock.json` لم تُنسخ إلى بيئة هذا الاختبار، لذا لا يُستنتج من النتيجة التحقق من تلك التعديلات.

قيد الاعتمادات: النسخة المثبتة المستخدمة للاختبار هي `ws@8.22.0`، بينما lockfile في النسخة المعزولة يحدد `8.22.1`. بعد قرار المالك ضُبط checkout الفعلي على `^8.22.2` وقُفل `8.22.2` باستخدام metadata محلية، لكن أرشيف `8.22.2` غير موجود في cache ولم تُحدَّث النسخة المثبتة. لا يثبت التشغيل الحالي التوافق مع الاعتمادات المقفولة الجديدة؛ لم يُجرَ تنزيل أو ترقية للحزمة المثبتة.

نجح لاحقًا اختبارا `tests/site-knowledge-search.test.ts` و`tests/site-knowledge-pagination.test.ts` على المسار الداخلي القائم، ونجح lint بعد إضافتهما. السلوك الأساسي كان منفذًا سابقًا، لذلك لا تُدّعى مشاهدة فشل سابق له ولا اكتمال تكامل MCP أو T048.

آخر تحقق مستهدف شمل 19 ملفًا و196 اختبارًا للميزة وIPC ونجحت فحوص lint وtypecheck وarch:check؛ استخدم بيئة الاعتمادات نفسها ذات القيد المذكور أعلاه.

فهرس codebase-memory لنفس checkout تحدّث تلقائيًا بعد تعديلات المصدر؛ فحص المسارات الأربعة `knowledge-draft.ts` و`knowledge-record.ts` و`knowledge-service.ts` و`knowledge-route.ts` أعاد `metadata_match` و`no_recorded_issue`، وهي إشارة best-effort وليست إثبات اكتمال الفهرس.
