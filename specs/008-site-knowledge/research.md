# بحث التصميم: معرفة الموقع

## R1 — فصل البيانات والتوافق

**Decision**: سجل مستقل لكل profile/origin، ولا تعديل لصيغ `SiteRecord` و`MapRecord` الحالية.  
**Rationale**: التحقق الحالي يرفض المفاتيح غير المعروفة ([site-record.ts](../../mcp-server/src/memory/site-record.ts)، [map-record.ts](../../mcp-server/src/memory/map-record.ts))، والتوسعة داخلها قد تجعل إصدارًا أقدم يعزل البيانات باعتبارها فاسدة. اسم hash ليس تشفيرًا. يستخدم المخزن owner-only وأدوات الملفات الآمنة القائمة، مع رفض نسخة مستقبلية دون الكتابة عليها.  
**Alternatives**: إضافة حقول للسجلات القائمة تغيّر عقدها؛ SQLite يزيد الاعتمادات والترحيل دون حاجة مقاسة.

## R2 — الهوية وحدود الثقة

**Decision**: اشتقاق profile من اتصال extension المحدد للجلسة وorigin من tab context، ورفض profile الافتراضي أو المكرر أو المتغير وincognito وvault المحمي أو المجهول. لا تقبل أدوات الوكيل profile أو origin للمصادقة من وسيطات يختارها.  
**Rationale**: [scope.ts](../../mcp-server/src/memory/scope.ts) يفحص هذه الحالات؛ [bridge-connections.ts](../../mcp-server/src/bridge-connections.ts) يسمح للعميل المقترن باختيار profile متصل. هذا فصل حسب profile المختار، لا تفويض مستقل لعميل عدائي. owner CLI امتياز محلي ولا يثبت عزلًا ضد مستخدم OS نفسه أو حامل IPC token؛ [SECURITY.md](../../SECURITY.md) يصف حد الثقة.  
**Alternatives**: اسم الوكيل أو حساب الصفحة لا يثبت الهوية؛ عزل حسابات الموقع مؤجل كما اختار المالك. عزل العملاء المقترنين أنفسهم يحتاج مصادقة وتفويضًا مستقلين ومراجعة للمتطلبات.

## R3 — موافقة محددة

**Decision**: prepare → preview كامل → owner confirmation → commit، بمسودة في ذاكرة daemon فقط، محدودة الحجم والمدة ومربوطة بـ session وconnection وprofile وorigin وoperation وrevision وcanonical payload digest؛ تُستهلك مرة واحدة ويعاد فحص كل القيم قبل commit. أي اختلاف أو انتهاء أو انقطاع أو عميل لا يستطيع تأكيد وعرض كامل المحتوى يؤدي للرفض.  
**Rationale**: [memory-policy.ts](../../mcp-server/src/tools/memory-policy.ts) يجرّد حقول تأكيد الوكيل ويستخدم form elicitation، لكن [register-tools.ts](../../mcp-server/src/register-tools.ts) يوفر prompt نصيًّا وboolean فقط. يجب اختبار عرض النص الكامل واختيار العناصر عمليًا. يقبل daemon أوامر IPC من العميل المحلي الموثوق؛ digest أو boolean ليسا إثباتًا ضد حامل token عدائي. وثائق [MCP SDK 1.32.2](https://github.com/modelcontextprotocol/typescript-sdk/blob/1.32.2/docs/capabilities.md) تصف form elicitation لإدخال غير حساس؛ لا تُرسل إليه بيانات معروفة الحساسية أو أسرار.  
**Alternatives**: الموافقة على ملخص مبتور أو موافقة عامة للجلسة لا تثبت قبول العناصر؛ حفظ draft على القرص يخالف عدم حفظ غير المعتمد. تُرفض المدخلات الأكبر من الحد بدل عرض مقتطف كأنه كامل.

## R4 — النص الحر والمعلومات الحساسة

**Decision**: قصر الإدخال على حقول وأنواع وحدود معروفة ومعاينة كاملة، ورفض الأسرار والبيانات الخاصة بالحساب والبيانات الشخصية/المالية افتراضيًا، مع فحص دفاعي ومراجعة بشرية. لا تُطبع القيم المرفوضة في errors أو logs أو export. يُعتبر كل نص موقع أو مصدر مستورد غير موثوق ولا يُنفَّذ كتعليمات.  
**Rationale**: فحص الأنماط لا يثبت خلو النص الحر من جميع الأسرار أو الأسماء؛ اختبار علامات مزروعة يثبت الحالات المختبرة فقط. تصنيفات الوكيل ادعاءات لا برهان مستقل؛ لا تُسند «فحص مباشر» أو «نجاح اختبار» إلا إلى دليل قابل للربط بنتيجته، وإلا تُعرض كتصريح غير متحقق. تُحظر روابط تتضمن credentials أو query/fragment، ولا تُقرأ الملفات المرتبطة تلقائيًا.  
**Alternatives**: allowlist مغلقة وحدها أكثر أمانًا لكنها لا تلبي الملاحظات المرنة؛ التنقيح الآلي وحده غير كافٍ. قرار المالك بشأن الخطر المتبقي بوابة مراجعة قبل التنفيذ.

## R5 — الذرّية والتزامن والحذف

**Decision**: writer واحد داخل daemon، تسلسل لكل `(profile, origin)`، فحص revision وجيل الحذف/السياسة قبل الاستبدال، دفعة واحدة في ملف واحد، ولا كتابة جزئية. إعادة محاولة request لها idempotency key مرتبط بالمحتوى والنطاق والنتيجة؛ بعد rename إذا تعذر إثبات fsync تُعاد `OUTCOME_UNKNOWN` ويُطلب فحص السجل قبل الإعادة. يُبطل الحذف أو التعطيل أو الاستبعاد المسودات ذات الصلة قبل commit.  
**Rationale**: [json-store.ts](../../mcp-server/src/core/json-store.ts) يوفر atomic replace ويميز نتيجة durability غير المؤكدة؛ [queue.ts](../../mcp-server/src/memory/queue.ts) يستخدم tombstones لإيقاف العمل المعلق. لا يضمن أي منهما transaction عبر عدة ملفات أو عمليات daemon. tombstones الحالية ليست سجلًا دائمًا ضد استعادة backup.  
الحذف الحالي لموقع أو لكل المواقع يجب أن يشمل مخزن 008: يُحظر الوصول أولًا ويُبطل المعلق، ثم تُحذف المخازن مع سجل تقدم محلي خالٍ من المحتوى للاستكمال بعد restart. عند فشل جزء لا يُبلَّغ بنجاح ولا تُكشف المعرفة المحجوبة؛ لا تُدّعى ذرّية عابرة للمخازن.  
**Alternatives**: batch موزع عبر ملفات يحتاج transaction/recovery إضافيين؛ قصر دفعة الحفظ على موقع/profile يجعل أثر الموافقة ذريًا بملف واحد. لا تشغيل متزامن لكاتبين خارجيين مدعومًا.

## R6 — النسخ والاستعادة

**Decision**: استعادة مدارة لكل موقع/profile فقط، من artifact يختاره المالك بعد التحقق من schema والحجم والصلاحيات؛ معاينة للنطاق والتحذير من استعادة محذوف، مع الموافقة على المحتوى والتأثير كاملين قبل atomic replace. لا تُحذف أو تُعدّل الذاكرة القديمة.  
**Rationale**: [operations-recovery.md](../../docs/operations-recovery.md) يصف إجراء استعادة خارجيًا وليس API شاملًا. لا يستطيع المنتج منع استعادة ملفات مباشرة خارج أدواته؛ لا يزعم الاحتفاظ بذاكرة حذف عبر نسخ قديمة.  
**Alternatives**: tombstone منفصل دائم لا يصمد عند استعادة الجهاز كاملًا إلا باعتماد خارجي؛ لا تَعِد به الخطة. الاستعادة متعددة الملفات مؤجلة إلى عقد transaction واضح.

## R7 — الأسماء والعقود والتحقق

**Decision**: أداتان مقترحتان `browser_site_knowledge` للقراءة و`browser_site_knowledge_manage` للإدارة، وعقد في [contracts/site-knowledge.md](contracts/site-knowledge.md). ربطهما بسجل الأدوات، schemas، wire allowlist، session gate، handler، daemon وcapability tests.  
**Rationale**: أسماء الأدوات وtimeouts تأتي من السجل ([registry.ts](../../mcp-server/src/tools/registry.ts))؛ لا تُضاف جداول سياسات موازية. القائمة والمعاينة والتصدير محدودة وبـ pagination. لا تعاد صياغة نص إدخال خطير في رسالة خطأ. لا يُعتمد على `scripts/memory.mjs` لتصدير كبير حتى يُختبر flush؛ لوحظ سابقًا اقتطاع خرج بعد 65536 بايت.  
**Alternatives**: توسيع `browser_memory` يخلط semantics الحالية بالمعرفة الحرة؛ أداة واحدة لكل العمليات تزيد سطح الكتابة وتقلل وضوح الأذونات.
